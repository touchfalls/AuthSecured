# Ручная проверка на сервере

Чеклист для ветки `security/hardening-after-1.2.7`. Автотесты проходят, но ничего из этого не запускалось на
настоящем сервере. Отмечайте пункты по мере проверки; если результат не совпал с ожидаемым, записывайте версию
сервера, лог и точные шаги.

## 0. Подготовка

- Серверы: Paper (offline-mode), Paper (online-mode), Folia, Fabric (одна версия 1.21.x и одна 26.x).
  Для пунктов 5, 9 и 12 нужны PostgreSQL и Velocity.
- Клиенты: два аккаунта (A и B) и два разных внешних IP (например, домашняя сеть и мобильная точка доступа).
  Для проверки параллельных команд удобен бот на mineflayer или клиент с макросом.
- Перед началом сохраните копии `auth.db` и мира. Для проверки обновления возьмите `auth.db` от 1.2.7 с
  несколькими аккаунтами и сессиями.
- Каждый пункт проверяйте и на Paper, и на Fabric, если не указано иное.

## 1. Запуск и миграции базы

- [ ] Чистый запуск на SQLite: в логе `SQLite database schema is at version 5`, рядом с `auth.db` появились
      `auth.db-wal` и `auth.db-shm`.
- [ ] Запуск на копии `auth.db` от 1.2.7: миграции проходят, старые аккаунты входят со своими паролями,
      сохранённые сессии работают.
- [ ] PostgreSQL: Flyway применил `V4` и `V5`; в таблице `accounts` есть `last_login_ip_hash`, `totp_secret`,
      `totp_enabled`, `totp_last_step`, `totp_backup_codes`.
- [ ] Два сервера на одной PostgreSQL: оба стартуют, регистрация на одном видна на другом.
- [ ] Откат: запуск старого jar 1.2.7 на базе версии 5 не должен портить данные (ожидаем отказ запуска со
      сообщением про более новую схему, а не молчаливое повреждение).

## 2. Пароль

- [ ] `/register` с паролем из 7 символов отклоняется, сообщение говорит «минимум 8».
- [ ] Пароль из 8 символов (например `x7Qp9zLm`) принимается.
- [ ] `security.password.min-length: 12` в `config.yml` и перезапуск: сообщение теперь говорит «минимум 12»,
      пароль из 8 символов отклоняется. Проверьте хотя бы en и ru (`language`).
- [ ] Частые пароли (`password123`, `Qwerty123`, `12345678`) отклоняются, регистр не важен.
- [ ] Пароль, равный нику (без учёта регистра), отклоняется при `/register` и `/changepassword`.
- [ ] Существующие аккаунты со старым паролем длиной 10 по-прежнему входят.

## 3. Ограничения до входа (Paper и Folia)

Для каждого пункта игрок не вошёл. Ожидаем: действие невозможно.

- [ ] Портал: выйдите, стоя в рамке Незера, и зайдите снова. Игрок остаётся в своём мире и не уходит через портал.
- [ ] Стойка для брони: правый клик по стойке не меняет экипировку.
- [ ] Инвентарь: перетаскивание стека по слотам (зажатая левая или правая кнопка) не работает, в том числе в
      крафтовой сетке 2x2.
- [ ] Предметы в руке: жемчуг, ведро, еда не используются. Если есть тестовый плагин, который отменяет только
      `useInteractedBlock`, предмет всё равно не срабатывает.
- [ ] Команды `/minecraft:tp`, `/plugin:cmd` и команды других плагинов блокируются; tab-complete показывает только
      разрешённые команды.
- [ ] Чат, подбор предметов, урон и голод по-прежнему заблокированы.
- [ ] После входа всё из этого снова работает.

## 5. Перебор и параллельные команды

- [ ] Offline-режим: игрок `Steve` зарегистрирован. Зайдите как `sTeve` и 5 раз введите неверный пароль. После
      этого настоящий `Steve` входит с верным паролем без ожидания.
- [ ] Лимит по IP по-прежнему срабатывает: много неверных попыток с одного IP блокируют этот IP.
- [ ] Бот отправляет 20 `/login` подряд для одного ника с неверным паролем: обрабатывается одна, остальные
      получают «слишком много попыток». Счётчик неверных попыток растёт на 1, а не на 20.
- [ ] Бот отправляет 20 `/login`, среди них одна с верным паролем во второй половине пачки: вход не должен
      проходить в обход блокировки после 5 неудач.
- [ ] После блокировки (5 неудач) верный пароль возвращает «аккаунт заблокирован» до окончания срока.
- [ ] Двойной быстрый `/login` с верным паролем: первый входит, второй не ломает состояние.

## 6. Дубликат входа (Paper)

- [ ] Offline-режим: A вошёл как `Steve`. С другого IP зайдите как `Steve`, затем как `sTeve`: оба получают отказ
      с сообщением, A остаётся онлайн и авторизованным.
- [ ] С того же IP зайдите как `Steve` повторно: старое соединение вытесняется, новое проходит обычный вход
      (после обрыва связи игрок возвращается без ожидания).
- [ ] Online-режим: обработчик ничего не блокирует (вход с другого IP заменяет старое соединение, как раньше).
- [ ] Velocity без проброса IP: все игроки с одним адресом, поведение допустимо (проверка не мешает входу).
- [ ] Fabric: защиты нет, это ожидаемо (в чеклисте как известное ограничение).

## 7. `/sessions`

- [ ] До входа `/sessions` отвечает «вы не авторизованы».
- [ ] После входа `/sessions` показывает 1; зайдите с второго сервера на общей БД и сравните число.
- [ ] `/sessions revoke`: игрок остаётся в игре, число становится 0; после выхода и входа нужен пароль.
- [ ] `/sessions абв` показывает подсказку по использованию (Paper) или ошибку синтаксиса (Fabric).
- [ ] Команда работает на Paper, Folia и Fabric.

## 8. Вход с нового адреса

- [ ] Первый вход после обновления (старый аккаунт, адрес не записан): уведомления нет.
- [ ] Второй вход с тем же IP: уведомления нет.
- [ ] Вход с другого IP (после выхода): сообщение о другом адресе, в `/authadmin audit` запись
      «вход с нового адреса».
- [ ] Восстановление сессии по IP (`session.verify-ip: true`) уведомления не показывает.

## 9. Двухфакторная защита (`/2fa`)

Используйте реальное приложение (Google Authenticator, Aegis, 1Password).

- [ ] `/2fa status` до включения: «выключена».
- [ ] `/2fa enable`: приходят ключ и ссылка `otpauth://`. Ключ вводится в приложении вручную; ссылка
      открывается на телефоне (или копируется в менеджер паролей).
- [ ] `/2fa confirm 000000`: «неверный код». `/2fa confirm <код>`: включено, показаны 8 резервных кодов.
- [ ] Выход и вход: после верного пароля сервер просит `/2fa <код>`, игрок остаётся неавторизованным
      (проверьте ограничения из пункта 3).
- [ ] Верный код: вход проходит. Тот же код во второй раз (в пределах 30 секунд) не проходит.
- [ ] Резервный код (в верхнем или нижнем регистре, с дефисом и без): вход проходит, повтор не проходит.
- [ ] 5 неверных кодов подряд: аккаунт блокируется так же, как после неверных паролей.
- [ ] `/2fa 123456` до `/login`: «нет входа, ожидающего код».
- [ ] Просидеть в ожидании кода дольше таймаута аутентификации: игрок кикается.
- [ ] Реконнект между `/login` и `/2fa`: код со второго соединения без нового `/login` не принимается.
- [ ] `/2fa disable <код>` с неверным кодом отклоняется; с верным (или резервным) отключает защиту.
- [ ] Включите защиту, затем выполните `/authadmin resetpassword <ник>`: проверьте, что вход по временному
      паролю работает без кода, а `/2fa status` потом показывает «выключена».
- [ ] В `logs/latest.log` и консоли коды и аргументы `/2fa` не видны (должно быть `[REDACTED]`).
- [ ] Старый `config.yml` без `/2fa` в `allowed-commands`: `/2fa <код>` до входа всё равно работает.
- [ ] Сменить `ip-secret` (или `AUTHSECURED_IP_SECRET`): вход с включённым `/2fa` должен падать с ошибкой в логе,
      а не пропускать без кода; верните секрет обратно.
- [ ] Пункты выше на Paper, Folia и Fabric.

## 10. Прокси и определение премиум-аккаунтов

- [ ] Velocity без проброса IP, два игрока онлайн: `/authadmin doctor` выдаёт предупреждение про общий
      локальный адрес. Включите modern forwarding: предупреждение исчезает.
- [ ] Один игрок онлайн: проверка показывает OK (это ожидаемо, она не может судить).
- [ ] `auth.online-mode.trust-proxy-uuid: false` (по умолчанию), Velocity online-mode, бэкенд offline:
      премиум-игрок обязан вводить пароль.
- [ ] `trust-proxy-uuid: true`, Velocity modern forwarding, бэкенд в offline и закрыт файрволом: премиум-игрок
      входит без пароля.
- [ ] То же, но игрок без лицензии (cracked) через прокси в offline-режиме или напрямую на бэкенд: пароль нужен.
- [ ] Игрок Bedrock через Floodgate: пароль нужен.
- [ ] Прямое подключение к бэкенду при открытом порту: вход без пароля невозможен.

- [ ] После остановки записи аудита последних входов на месте.
- [ ] SQLite под параллельной записью (регистрации, входы, аудит): нет ошибок `database is locked` и
      `INTERNAL_ERROR`.

## Известные ограничения

- Защита от дубликата входа есть только на Paper.
- Определение премиум-аккаунтов работает только за доверенным online-прокси; прямой offline-сервер ник не
  проверяет.
- QR-кода для `/2fa` нет; ключ вводится вручную или по ссылке.
- Уведомление о новом адресе не показывается при восстановлении сессии и не отправляется в Discord/Telegram.
- Проверка контрольных сумм зависимостей Gradle (`verification-metadata.xml`) не включена: `paper-api` берётся как
  `1.21-R0.1-SNAPSHOT`, у снапшота нет постоянной суммы, и Gradle не может его записать.
- Проверка `doctor` про общий локальный адрес срабатывает только при двух и более игроках онлайн.
